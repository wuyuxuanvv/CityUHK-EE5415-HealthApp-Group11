# HealthApp 产品需求文档

## 1. 项目背景

HealthApp 是香港城市大学 EE5415 Group 11 的六人课程项目。它是一款单设备、单用户的个人健康管理 Android 应用，所有数据保存在本机，不依赖后端或网络服务。

## 2. 项目目标

- 在一个 App 中记录运动、饮食和睡眠数据。
- 通过首页、历史记录和每周趋势帮助用户了解执行情况。
- 使用统一的 Room 数据库，支持六名成员并行开发和最终合并。
- 结果仅用于日常记录。热量为估算值，睡眠评价不是医疗诊断。

## 3. 主要使用场景

1. 首次使用时填写身高、体重、年龄、性别及三个健康目标。
2. 从动作库选择动作，填写日期和时长，保存一次实际运动。
3. 按星期设置运动计划，完成后对当天计划打卡。
4. 搜索食物，选择早餐、午餐、晚餐或加餐并填写克数。
5. 填写完整入睡和起床时间，自动计算跨午夜的睡眠时长。
6. 在首页查看当天运动次数、当天摄入热量和最近一晚睡眠。
7. 查看历史与每周趋势，并按固定、可解释规则获得目标建议。

## 4. 六个功能模块

### 4.1 个人资料（成员 1）

- 保存身高（cm）、体重（kg）、年龄和性别。
- 保存每周运动目标次数、每日摄入目标（kcal）和每日睡眠目标（分钟）。
- 只支持一个本地用户，固定使用 `UserProfile.SINGLE_USER_ID`。
- 用户可查看和修改资料，重启后数据仍存在。
- 本地 PIN 设置、锁定和解锁：待开发。PIN 不代表远程账号。

### 4.2 运动（成员 2）

- 最终动作库不少于 20 项，每项含名称、分类、MET 和演示资源标识。
- 实际记录只包含动作、日期、运动时长和估算热量，不使用组数、次数或重量。
- 估算公式：`MET × 体重(kg) × 时长(分钟) ÷ 60`，界面必须标注“估算”。
- 支持实际记录的查看、编辑和删除。
- 每周计划按星期、动作和目标时长保存；实际记录、计划、打卡是三类独立数据。

### 4.3 饮食（成员 3）

- 最终食物库不少于 100 项，包含每 100g 的热量、蛋白质、碳水、脂肪及图片资源标识。
- 支持食物搜索。
- 餐次只允许 `BREAKFAST`、`LUNCH`、`DINNER`、`SNACK`。
- 用户填写摄入克数，应用计算并保存本次实际营养值。
- 支持饮食记录查看、编辑、删除和指定日期总热量。
- 不建设复杂饮食计划；每日热量目标统一来自个人资料。

### 4.4 睡眠（成员 4）

- 保存完整的入睡 epoch milliseconds、起床 epoch milliseconds、时长（分钟）和归属日期。
- 归属日期统一为用户起床时的本地日期，格式 `yyyy-MM-dd`。
- 起床时间必须晚于入睡时间，跨午夜可正确计算。
- 支持记录查看、编辑、删除及相对目标的简单时长评价。
- 不记录深睡、浅睡、平均心率，不接入穿戴设备，不进行医疗诊断。

### 4.5 首页与统计（成员 5）

- 首页展示当天实际运动记录数、当天实际摄入 kcal、最新一条睡眠记录时长。
- 无记录时显示空状态；缺失睡眠不能当作 0 分钟。
- 支持日期范围内历史记录和每周趋势，使用公共数据接口，不复制数据库。
- 第一版采用简单列表或图表，不建设复杂可视化系统。

### 4.6 扩展功能（成员 6）

- 根据资料目标和真实记录给出固定规则建议，用户确认前不得改目标。
- 使用 Android 本地通知提供每日记录提醒。
- 提供带二次确认的全部数据清除。
- 负责跨模块测试和最终演示检查。
- 不接入 AI/大语言模型 API。

## 5. 用户流程

首次启动 → 进入资料页保存资料与目标 → 通过底部导航进入各记录页 → 新增/编辑/删除真实记录 → 首页异步读取 Room 汇总 → 查看历史或趋势 → 可选启用提醒或查看规则建议。

## 6. 优先级

- P0：统一数据库、五页导航、资料保存、三类记录 CRUD、正确单位/时间规则、首页真实汇总、稳定构建。
- P1：动作库、食物库、运动计划与打卡、历史记录、每周趋势、输入校验。
- P2：本地 PIN、目标建议、本地提醒、数据清除、视觉完善和演示测试。

## 7. 非功能需求

- Java + XML + Android Views；单 `app` module。
- Room 操作禁止运行在 UI 主线程，禁止 `allowMainThreadQueries()`。
- 不请求 `INTERNET` 权限，不添加后端、云数据库或远程登录。
- 公共日期、单位、Entity 和接口保持一致；空数据必须明确展示。
- 采用 Material Components，支持五个主页面稳定切换。

## 8. 当前不开发

远程账号、多用户、网络同步、云数据库、AI 推荐、复杂饮食周计划、穿戴设备、深浅睡/心率、医疗诊断和复杂动画均不在第一版范围内。

## 9. 当前公共框架完成情况

已实现：Java/XML 工程转换、五页底部导航、六个模块入口、统一 Room Entity/DAO、异步跨模块 `HealthRepository`、真实首页空状态、日期与计算工具、基础单元测试。

待开发：资料表单与 PIN、动作/食物初始库、各业务 CRUD 页面、计划打卡、历史趋势、规则建议、通知、清除确认和完整跨模块测试。

## 10. 最终验收标准

1. Debug APK 可构建并在模拟器启动，五个底部导航页面可切换。
2. 资料和所有记录均持久化到唯一 `health_app.db`。
3. CRUD、MET 与营养计算、跨午夜睡眠计算均正确。
4. 首页与趋势只显示真实数据库结果，空数据语义正确。
5. 不存在 UI 主线程数据库查询、网络权限或重复数据库。
6. 六名成员的代码边界、接口和 Git 协作符合项目文档。
